// Command flow — 4-step RTT-tracked confirmation gate // Prevents accidental commands; logs every step for audit type CmdState = 'idle'|'pending'|'armed'|'executing'|'done' async function executeCommand( acId: string, cmd: AircraftCommand, adapter: AircraftAdapter ): Promise<CommandResult> { const log = auditLogger.begin({ acId, cmd, operator: auth.userId() }) const t0 = Date.now() // Step 1 — show intent in UI, require explicit confirm const confirmed = await ui.confirmDialog({ title: `Execute ${cmd.type} on ${acId}?`, severity: cmd.severity }) if (!confirmed) { log.cancel(); return { status: 'cancelled' } } // Step 2 — arm command (pre-flight safety check) dispatch(setCmdState({ acId, state: 'armed' })) await adapter.arm() // Step 3 — execute with RTT tracking dispatch(setCmdState({ acId, state: 'executing' })) await adapter.setMode(cmd.mode) const rtt = Date.now() - t0 // Step 4 — verify ack and log outcome log.complete({ rtt, success: true }) metrics.histogram('cmd.rtt', rtt, { cmd: cmd.type }) dispatch(setCmdState({ acId, state: 'done' })) return { status: 'success', rttMs: rtt } }

✦ Engineering Manager's Thinking ✕

Architecture Principles

  • WebSocket + RAF batching: raw 10 Hz MAVLink frames coalesced into one Redux batch per animation frame. This keeps React render budget under 16 ms even with 3+ aircraft streaming simultaneously.
  • Aircraft Adapter interface: GUI never talks to hardware directly. PixhawkAdapter, ArduPlaneAdapter, and SimAdapter are all swappable. CI runs entirely against SimAdapter — no physical aircraft needed.
  • Offline-first ring buffer: 300-frame history per aircraft in Redux. Field ops lose connectivity; GCS must stay useful during link dropouts. History drives sparklines and incident replay.
  • Command gate (4-step): Show → Confirm → Arm → Execute with full RTT tracking and append-only audit log. Every operator action is attributable. Required for Transport Canada compliance.

First Two Hires

  • Generalist full-stack (P0): Owns the GCS frontend end-to-end. Needs React + TypeScript depth and genuine interest in avionics/embedded. This isn't a pure web role — they'll be on the flight line.
  • Geospatial specialist (P1): MapLibre GL, terrain tile pipelines, airspace data (NAV CANADA, Eurocontrol). Current SVG map is a proof-of-concept; production needs real tiled maps with TFR overlays from live feeds.

Near-Term Roadmap Risks

  • Flight-test windows are hard constraints. SFOC windows from TC don't move. Everything in the sprint must ship before the next window or it blocks a quarter of revenue.
  • Video latency budget: Current WebRTC pipeline is 71% quality on RB-H1. Need to profile whether that's RF or codec. Operator decisions depend on video; degraded feed = grounded aircraft.
  • Magnetometer calibration on RB-01: Shows CALIB in health panel. Must resolve before DND-FW-05 or we fly with compass anomaly. Add pre-flight calibration step to checklist gate.

Onboarding Standard

New hire must be able to run a full sim flight on day one: pnpm gcs-sim → connect GCS → upload mission → arm → AUTO → RTL → land. If that loop isn't runnable locally without external deps, it's a team problem not a hire problem.
